## 1. RÉPONSES AUX CONTRÔLES ARCHITECTURAUX

### Question 1 : QR Architecture Validée ?
**YES**  
Le parcours actif d'activation de licence utilise [LicenseActivationModal.tsx](file:///d:/app%20canaris/28+/src/features/licensing/components/LicenseActivationModal.tsx) (déclenché depuis le badge `LicenseStatusBadge` et `Parametres.tsx`).  
Un 4ème onglet dédié (`[Scanner QR]`) monte directement [QrCodeScannerModal.tsx](file:///d:/app%20canaris/28+/src/features/licensing/components/QrCodeScannerModal.tsx). Le payload décodé est transmis à `LicensingService.getInstance().importOfflineBetaLicense(payload)` sans aucune modification ni duplication de la logique cryptographique LMSE.

### Question 2 : PDF Android Architecture Validée ?
**YES**  
La méthode défaillante `<a download="blob:...">` et `window.print()` est abandonnée sur Android.  
Le nouveau pipeline Android natif suit la séquence :  
`generate PDF (%PDF-1.4)` → `validate PDF (MIME + %PDF- + %%EOF)` → `Capacitor Filesystem.writeFile()` → `Fichier .pdf réel sur disque Android` → `URI Native file://` → `Capacitor Share.share({ url: fileUri })` → `Lecteur PDF Native Android`.

### Question 3 : Capacitor Filesystem Disponible ?
**YES**  
Le plugin officiel `@capacitor/filesystem` (v8) est intégré pour écrire le fichier PDF binaire réel (`Uint8Array` / Base64) sur le disque local d'Android (`Directory.Cache` ou `Directory.Documents`) et obtenir une URI native valide.

### Question 4 : Capacitor Share Disponible ?
**YES**  
Le plugin officiel `@capacitor/share` (v8) est intégré pour transmettre l'URI native du fichier PDF écrit sur le disque Android vers le framework de partage et d'ouverture de document d'Android 16.

### Question 5 : Native PDF Opening Possible ?
**YES**  
L'association de `@capacitor/filesystem` et `@capacitor/share` permet l'ouverture et l'impression directes des rapports PDF dans les applications clientes Android (Google PDF Viewer, Adobe Reader, Samsung PDF Viewer, etc.).

### Question 6 : Plugins Existants Réutilisables ?
L'infrastructure Capacitor 8 existante (`@capacitor/core`, `@capacitor/android`) est conservée et complétée de façon minimale par les 3 plugins officiels Capacitor 8 de référence : `@capacitor/filesystem`, `@capacitor/share`, et `@capacitor/camera`.

### Question 7 : Data URI Conservé Uniquement Comme Web Fallback ?
**YES**  
Le Data URI (`data:application/pdf;base64,...`) et le téléchargement Blob Web ne sont conservés qu'en solution de repli pour navigateurs Web Desktop uniquement. Sur Android 16, le stockage physique natif + URI file:// est le chemin obligatoire.

### Question 8 : LMSE Untouched ?
**YES**  
100% de la couche cryptographique LMSE (RSA-2048, SHA-256, validation de signature, `DeviceFingerprintEngine`, `maxDevices`, politiques d'expiration) demeure **strictement intacte et inchangée**.

## 2. GESTION STRICTE DES ERREURS D'EXPORTATION
Si la génération PDF réussit mais que l'écriture disque avec `Filesystem.writeFile()` ou l'obtention de l'URI native échoue sur Android, le système **NE retournera JAMAIS un faux succès**. L'opération retournera un statut `{ success: false, message: "Erreur lors de l'écriture du fichier PDF sur le stockage Android." }` avec alerte visuelle i18n appropriée.
