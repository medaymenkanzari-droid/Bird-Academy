## Analyse Détaillée par Bug

### BUG-01 — Activation licence au premier démarrage
- **BUG** : Sur une installation vierge, l'application rendait temporairement les modules ou le WelcomeWizard avant la fin de l'évaluation de licence.
- **CAUSE RACINE** : Le hook `useLicensing` démarrait en état asynchrone sans bloquer explicitement le rendu de `App.tsx`. `App.tsx` déclenchait le wizard d'accueil indépendamment du statut de validation de la licence.
- **PREUVE** : Inspecté dans `App.tsx` (lignes 85-90) où `useEffect` vérifiait `bird_academy_wizard_completed` sans attendre `licenseState === 'LICENSE_VALID'`.
- **FICHIER RÉELLEMENT UTILISÉ** : [src/App.tsx](file:///d:/app%20canaris/28+/src/App.tsx), [src/features/licensing/hooks/useLicensing.ts](file:///d:/app%20canaris/28+/src/features/licensing/hooks/useLicensing.ts)
- **CORRECTION** :
  1. Implémentation d'une machine d'état stricte : `INITIALIZING` -> `LICENSE_REQUIRED` | `LICENSE_VALID` | `LICENSE_INVALID`.
  2. Guard dans `App.tsx` : Aucun module, aucun dashboard, aucun wizard ne peut être rendu si `licenseState !== 'LICENSE_VALID'`.
  3. Ajout des logs de diagnostic `LICENSE-BOOT-01` à `LICENSE-BOOT-05` sans exposition de données cryptographiques sensibles.
- **TEST AUTOMATIQUE** : `tests/first-launch-license-v135.test.ts` (PASS).
- **BUNDLE & APK** : Intégré et vérifié dans le bundle web et l'APK compilé.

### BUG-02 — Occupation des cages (0% / 00 oiseaux)
- **BUG** : Le tableau de bord affiche 50 oiseaux, mais le module Cages affichait `00` oiseaux présents et `0%` d'occupation.
- **CAUSE RACINE** : `HabitatEngine.calculateStats('facility', ...)` filtrait les oiseaux par `b.facilityId` ou `b.zoneId`. Dans la base de données, les 50 oiseaux possèdent uniquement `cage_id` ou `cageId` (ex: `cage_id: 1`). L'évaluation retournait donc 0 oiseau présent pour l'installation globale.
- **PREUVE** : Inspecté dans `HabitatEngine.ts` (lignes 123-127).
- **FICHIER RÉELLEMENT UTILISÉ** : [src/business/HabitatEngine.ts](file:///d:/app%20canaris/28+/src/business/HabitatEngine.ts), [src/features/habitat/components/HabitatComponent.tsx](file:///d:/app%20canaris/28+/src/features/habitat/components/HabitatComponent.tsx)
- **CORRECTION** :
  1. Résolution des oiseaux par association directe des identifiants de cages (`b.cage_id`, `b.cageId`) dans `calculateStats`.
  2. Prise en compte de la volière par défaut `fac_default` pour agréger l'ensemble des cages actives.
  3. Ajout des logs de diagnostic `CAGE-DATA-01` à `CAGE-DATA-05`.
- **TEST AUTOMATIQUE** : `tests/cages-data-v135.test.ts` (PASS).
- **BUNDLE & APK** : Intégré et vérifié dans le bundle web et l'APK compilé.

### BUG-03 — Retour liste des cages & Hardware Back
- **BUG** : Impossible de revenir proprement de la vue détail de cage vers la liste globale.
- **CAUSE RACINE** : `App.tsx` monte `<HabitatComponent />` (`src/features/habitat/components/HabitatComponent.tsx`). Le composant `Cages.tsx` précédemment modifié n'était pas le composant affiché par l'application. `HabitatComponent` ne possédait aucun écouteur d'événement `popstate` pour gérer le bouton retour matériel Android.
- **PREUVE** : Inspecté dans `App.tsx` (ligne 804) : `case 'cages': return <HabitatComponent ... />`.
- **FICHIER RÉELLEMENT UTILISÉ** : [src/features/habitat/components/HabitatComponent.tsx](file:///d:/app%20canaris/28+/src/features/habitat/components/HabitatComponent.tsx)
- **CORRECTION** :
  1. Implémentation d'une stratégie de navigation unifiée dans `HabitatComponent` gérant `selectedType` et `selectedId`.
  2. Ajout de `window.addEventListener('popstate')` pour capturer le retour matériel Android.
  3. Fonctions `selectNode` (avec `pushState`) et `resetSelection` (réinitialisant à `selectedType='all'`, `selectedId='all'`).
- **TEST AUTOMATIQUE** : `tests/cages-navigation-v135.test.ts` (PASS).
- **BUNDLE & APK** : Intégré et vérifié dans le bundle web et l'APK compilé.

### BUG-04 à BUG-07 — Débordement horizontal mobile (Overflow)
- **BUG** : Débordement horizontal de l'écran sur les modules Statistiques, Génétique, Référentiel et Intelligence sur petits écrans (360px - 412px).
- **CAUSE RACINE** : En flexbox CSS, les conteneurs enfants possèdent une valeur par défaut `min-width: auto`. Les barres d'onglets horizontales et graphiques sans `min-w-0` sur les éléments parents forçaient le document entier à s'élargir au-delà de `window.innerWidth`.
- **PREUVE** : Propriétés CSS des wraps dans `AppPage.tsx`, `AnalyticsDashboard.tsx`, `GeneticsDashboard.tsx`, `ReferenceBiologique.tsx`, et `IntelligenceDashboard.tsx`.
- **FICHIERS RÉELLEMENT UTILISÉS** :
  - [src/components/design-system/AppPage.tsx](file:///d:/app%20canaris/28+/src/components/design-system/AppPage.tsx)
  - [src/features/analytics/components/AnalyticsDashboard.tsx](file:///d:/app%20canaris/28+/src/features/analytics/components/AnalyticsDashboard.tsx)
  - [src/features/genetics/components/GeneticsDashboard.tsx](file:///d:/app%20canaris/28+/src/features/genetics/components/GeneticsDashboard.tsx)
  - [src/components/ReferenceBiologique.tsx](file:///d:/app%20canaris/28+/src/components/ReferenceBiologique.tsx)
  - [src/features/intelligence/dashboards/IntelligenceDashboard.tsx](file:///d:/app%20canaris/28+/src/features/intelligence/dashboards/IntelligenceDashboard.tsx)
- **CORRECTION** :
  1. Ajout des classes `min-w-0`, `w-full`, `max-w-full` sur les conteneurs racines et flexbox parents.
  2. Maintien du défilement local (`overflow-x-auto`) uniquement sur les barres d'onglets sans élargir la page.
  3. Garantit `document.documentElement.scrollWidth === window.innerWidth`.
- **TEST AUTOMATIQUE** : `tests/mobile-overflow-v135.test.ts` (PASS).
- **BUNDLE & APK** : Intégré et vérifié dans le bundle web et l'APK compilé.
